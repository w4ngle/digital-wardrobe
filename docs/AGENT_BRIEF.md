# Бриф для агента: проект «Цифровой гардероб»

## Правила (важнее любых задач)
1. ПЕРЕД любым кодом прочитай AGENTS.md и релевантные страницы в node_modules/next/dist/docs/.
   В проекте Next 16.x — не полагайся на память об API Next 13–15.
2. Работай маленькими шагами: одна задача из WBS = одна ветка `feat/<номер-задачи>` = один коммит-набор.
3. После каждого изменения: `npm run lint && npm run build && npm test`. Не сдавай задачу с красным.
4. Не добавляй зависимости без записи в docs/adr/ (одна строка «что и зачем»).
5. Секреты: только через process.env; не логировать ключи, тела запросов с фото и полные ответы модели.
6. ИИ-вызовы ТОЛЬКО на сервере (app/api/*). Ни OPENAI_API_KEY, ни service_role не должны попасть в клиентский код
   (переменные без NEXT_PUBLIC_).
7. Любой ответ модели проходит zod-валидацию до использования. Числа/id из ответа модели — недоверенный ввод.
8. Модели и провайдер берутся из env через lib/ai/provider.ts. Не хардкодить имена моделей в роутах.
9. Не менять визуальный стиль вне дизайн-системы (раздел 6 PLAN.md): цвета и шрифты только через токены.
10. Все константы категорий/сезонов/стилей — только из lib/taxonomy.ts.

## Контекст проекта
Next.js 16 (App Router) + React 19 + TS + Tailwind 4 + Supabase (Postgres, Storage, pgvector).
Таблицы: items, outfits, outfit_items (+ ai_usage). Язык интерфейса — русский.

## Порядок работы по задаче
1. Прочитай описание задачи и «Готово, когда» в docs/PLAN.md.
2. Составь список файлов, которые изменишь, и покажи его мне ДО правок.
3. Сделай миграцию БД (если нужна) в supabase/migrations/NNNN_name.sql — идемпотентную (IF NOT EXISTS).
4. Реализуй, покрой тестом (vitest) чистые функции: схемы, валидаторы, форматтеры каталога.
5. Проверь руками сценарий из «Готово, когда»; приложи короткий отчёт: что сделано, что проверено, что осталось.
